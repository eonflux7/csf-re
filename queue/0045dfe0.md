# Escalation 0x0045DFE0: Opus review found behavior differences (file kept)

- 0x0045DFEC-0x0045DFEF: the original does fld dword [ecx+4] then __ftol2, a signed float->int64 truncation whose low 32 bits (eax) are pushed at 0x0045E000 as the argument to 0x468E20. The reimplementation uses static_cast<int>(static_cast<uint64_t>(slotValue)), an unsigned 64-bit conversion. For negative floats (e.g. -1.0f, which the original turns into 0xFFFFFFFF) this is undefined behaviour and on modern compilers gives a different value (0 or saturated), so the wrong index can reach SceneEntryIndexFromFloat. It should be a plain signed cast, static_cast<int>(slotValue).
