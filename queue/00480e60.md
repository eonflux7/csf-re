# Escalation 0x00480E60: Opus review found behavior differences (file kept)

- Missing store of 3 to the hit-info header at [ebp-0xB0] (pseudocode `v38 = 3`, written just before the vtbl+0x34 trace call in the 0x480E60 body; no asm address available in the packet). The original passes that same object to CharActionFsm_InitializeHitInfo(&v38) and then to hit->vtbl[0xC](&v38). The reimplementation zero-initialises `hitInfo` so the header is 0 instead of 3, which the callees will observe unless InitializeHitInfo unconditionally overwrites that field (it is still a todo, so this is unconfirmed).
