## Orchestrator notes (2026-10-12)
- The rejected file is right: the original is `fld z; fld y; fld x; ...; fsqrt` (six x87 slots deep), ours is the
  same sum. "orig -nan(ind), ours 0" for a zero vector is the x87 stack overflowing in the original: three or
  more entries were already live at entry. Ours needs one slot, so it still answers.

  binding of a tier-3 replayed fp callee is declared float, and the gate's st0 fact agrees with a stack-depth
  simulation on all 6,301 functions the simulation can decide (work/emu_t3/x87depth.py).
- hook/diff.cpp now logs `X87 <addr> ...: N x87 entries live at entry (last clean entry ...)` (first 20): the next
  smoke shows where the leak starts. Same suspect for 0x47E350 (NaN vectors reaching RenderWare under load).
- Put the file back once the leak is found; nothing to change in it.
